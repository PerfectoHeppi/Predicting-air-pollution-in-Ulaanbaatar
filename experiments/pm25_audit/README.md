# Улаанбаатарын PM2.5 загварын аудит

Локал ажлын хавтасны `peak` горимыг GitHub-ийн `main` дэх `412c93d` хувилбартай тулгав. GitHub-д долоо хоногоор бүлэглэх, early stopping, CatBoost, SHAP, hyperparameter хайлт болон АНУ-ын ЭСЯ-ны PM2.5 архив нэмэгдсэн. [GitHub дээрх commit-үүд](https://github.com/PerfectoHeppi/Predicting-air-pollution-in-Ulaanbaatar/compare/382f1f4...412c93d)

## Үнэлгээний нөхцөл

- Сургалтын 94,009 мөр, 159 долоо хоног, тестийн 25,078 мөр, 40 долоо хоногийг шалгав. Train/test хооронд долоо хоног, ID, станц–цагийн хослол давхцаагүй. Файл бүр дотор станц–цаг давтагдаагүй.
- Ижил таван гаднах хуваалтыг `seed=42`-оор үүсгэв. Нэгдсэн OOF RMSE-д мөр бүрийн квадрат алдааг ашиглав. 47 долоо хоногийн локал holdout нь 26,922 мөртэй бөгөөд таван хуваалттай давхцана.
- Baseline нь тэмцээний анхны зургаан оролт, 400 boosting алхамтай. Харьцуулсан үндсэн LightGBM болон CatBoost нь ижил станц, цаг агаар, ERA5 оролттой.
- Шинэ LightGBM-ийн 63/95 навч, навч дахь 80/55 мөр, 0.065/0.085 learning rate, 95/63 bin, 0/4 L2 бүхий хоёр багц, 200/350/500 алхмыг гаднах сургалтын хэсгээс салгасан дотоод долоо хоногуудаар харьцуулсан. CatBoost-ийн 250/450/650 алхмыг мөн дотоод хэсгээр сонгов. Гаднах мөрийн `pm25` утга тохиргоо сонгох явцад ашиглагдаагүй.
- Нэмэлт оролтод 3/12/48 цагийн агаар сэлгэлтийн минимум, температурын дундаж, салхины вектор ба 12 цагийн түүх, 10–100 м салхины хурдны зөрүү, станц ба ERA5-ийн температур/чийгийн зөрүү, температурын анхны missing flag орсон.
- Blend-ийн жинг урьдчилан тогтоосон. `Peak + tuned` нь 50/50, CatBoost орсон хувилбар нь 50/40/10. Долоо хоногоор блоклон 4,000 удаа дахин түүвэрлэж, OOF RMSE-ийн хосолсон зөрүүний тодорхой бус байдлыг тооцсон.

## Leakage ба GitHub-ийн хэмжилт

1. Embassy loader нь `s.shift(-k)`-аар `t+1…t+4` цаг болон төвлөсөн 12/24 цагийн цонхоор `t+5`/ `t+11` хүртэлх хэмжилт оруулдаг. Энэ нь тухайн цагт бэлэн оролтоор таамаглах нөхцөлд look-ahead leakage үүсгэнэ. Архивын `Date (LT)` багана нь хүчинтэй мөрийн Year/Month/Day/Hour-тай таарсан. Станцын цагтай системтэй хоёр цагийн зөрүүг нотлох мета өгөгдөл репозиториос олдоогүй. [Embassy loader](https://github.com/PerfectoHeppi/Predicting-air-pollution-in-Ulaanbaatar/blob/412c93d/baseline_lightgbm_pm25.py#L22-L39)
2. Ижил цагийн Embassy–зорилтот хэмжилтийн яг тэнцүү хувь станц тус бүрд 0–2.97% байв. Шалгасан өгөгдөлд зорилтот цувааг шууд хуулсан шинж илрээгүй. Embassy-ийн дотоод цагийг ашигласан 2–24 цагийн лагийг тусад нь хэмжсэн. `t-2` нь train-ийн 85.17%, test-ийн 80.57%-д байгаа. Хоёр цагийн саатал нь туршилтын таамаглал бөгөөд CSV-д нийтлэгдсэн цаг алга. [EPA AirNow Embassy архив](https://gispub.epa.gov/airnowembassy/)
3. GitHub кодны early stopping нэг holdout дээр 545 мод сонгоод үүнийг 5-fold-д дахин хэрэглэдэг. SHAP-аар хасах feature сонгохдоо мөн тэр holdout-ыг ашигладаг. Эдгээр алхмууд үнэлгээний шошгыг сонголтод ашигладаг. Тохируулга идэвхжвэл хайлтын шилдэг CV оноог мөн хайлтад ашигласан хуваалтаас хэвлэдэг. [Early stopping болон CV](https://github.com/PerfectoHeppi/Predicting-air-pollution-in-Ulaanbaatar/blob/412c93d/baseline_lightgbm_pm25.py#L172-L256)
4. GitHub-ийн `interpolate(method="time")` нь температур нөхөхдөө дараагийн ажиглалтыг ашиглаж чадна. `temp_missing` нь нөхөлтийн дараах хоосон утгыг тэмдэглэдэг. Шинэ туршилтад анхны missing flag ашиглав. [Температурын нөхөлт](https://github.com/PerfectoHeppi/Predicting-air-pollution-in-Ulaanbaatar/blob/412c93d/baseline_lightgbm_pm25.py#L98-L136)
5. GitHub-ийн 47 долоо хоногийн holdout нь 29,097 мөртэй бөгөөд локал holdout-тай 10 долоо хоног давхцана. Кодны LightGBM-ийг дахин ажиллуулахад holdout RMSE **74.83**, анхны `GroupKFold`-ийн дундаж **75.01 ± 9.22**, OOF **75.57** гарсан. Эдгээрт ирээдүйн Embassy утгууд орсон. Repo-д байсан CatBoost логийн **89.38** нь Embassy нэмэхээс өмнөх `a83bcef`-ийн early-stopping хэмжилт. [CatBoost лог](https://github.com/PerfectoHeppi/Predicting-air-pollution-in-Ulaanbaatar/blob/a83bcef/catboost_info/catboost_training.json)
6. Энэ үнэлгээ нь түүхийн дундах алга болсон долоо хоногуудыг нөхөх нөхцөлтэй. Ирээдүй рүү таамаглах гүйцэтгэлийг хэмжихэд хугацаагаар урагшлах validation ба тухайн үед нийтлэгдсэн цаг агаарын forecast шаардлагатай. ERA5 нь түүхэн reanalysis. [Open-Meteo түүхэн өгөгдөл](https://open-meteo.com/en/docs/historical-weather-api)

## Дахин ажиллуулах

LightGBM 4.7.0, CatBoost 1.2.10 болон Python 3.14 ашиглав. ERA5 JSON-ийн SHA-256 нь `fcaf18b046e73d4ea6fab6b2eb666282d380b40dfd1f7f4f73b682f3df1f7798`. `--weather-json`-ыг өгөхгүй бол скрипт үндсэн загварын ERA5 таталтыг ашиглана.

`benchmark.py` нь `--fold 0`-д holdout, `--fold 1`–`5`-д OOF таамаглал гаргана. `--stage`-ийн `current`, `features`, `catboost`, `embassy` утга тус бүрийн гаралтыг `<stage>-<fold>.csv` нэрээр нэг түр хавтсанд хадгалснаар `summarize.py` бүх мөрийг шалгаж, хүснэгт болон хосолсон зөрүүг хэвлэнэ. `embassy` шатанд `412c93d` commit-ийн `Data/embassy` архивыг `--embassy-dir`-ээр заана.

[Submission CSV](submission.csv)-ийн 25,078 ID-г `sample_submission.csv`-ийн дараалалтай тулгаж, утга бүр төгсгөлтэй бөгөөд сөрөг биш болохыг шалгасан. Бүх 94,009 сургалтын мөрөөр сургахад tuned LightGBM-д 63 навч, 500 алхам, CatBoost-д 650 алхам сонгогдсон. Репозиторийн эх файл, үндсэн README болон өмнөх submission-ийн SHA-256 утгууд аудитын эхэн үеийнхтэй таарсан.
